# Support

Where to take a question, so it reaches someone who can answer it.

| Your question is about | Take it to |
| --- | --- |
| How some code works, a bug, a feature idea | An issue in the relevant repository |
| How to contribute, branches, pull requests | [CONTRIBUTING.md](CONTRIBUTING.md) |
| Getting access to a repository | Your project lead, or the Organisation Owner |
| Whether data may be stored in GitHub | Your project lead — **ask before committing, not after** |
| Licensing, publishing, making something public | Your project lead or the Organisation Owner. Never decide this alone |
| A security problem or an exposed credential | [SECURITY.md](SECURITY.md) — privately, never a public issue |
| Conduct concerns | [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) |

## Do not post publicly

Whether an issue is in a public or a private repository, do not include:

- participant information of any kind, including identifiers and linkage keys
- physiological recordings, or audio, video or images of participants
- health information
- passwords, API keys, tokens, certificates or other credentials
- unpublished results, partner information, or commercially sensitive detail

A private repository is not a safe place for this material either. If you need to share something sensitive to get help, ask your project lead how — do not paste it into an issue and delete it afterwards, because it stays in the record.

## Response times

The Studio is small. Expect a reply within a few working days, and follow up if you do not get one.
